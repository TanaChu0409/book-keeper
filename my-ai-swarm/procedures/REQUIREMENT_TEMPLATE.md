# 標準需求提交模板 (REQUIREMENT_TEMPLATE)

> **版本**：v2.0.0 | **用途**：確保每次需求都能正確自動路由到對應的工作流程

---

## 📋 使用說明

當您需要提交功能需求、優化建議、或尋求 AI Swarm 協助時，**請使用以下模板填寫**。

系統會根據您的回答 **自動判斷** 應該啟動哪個工作流程（A/B/C）。

## 🚀 提交流程

### 若流程判斷為 A（複雜）

1. 將此模板發送給 **@dotnet-architect**
2. Architect 產出設計計畫
3. 申請 **@dotnet-impact-validator** 評估
4. 評估完成後，交由 **@dotnet-developer** 實裝
5. 最後由 **@dotnet-qa-reviewer** 審查
6. **@dotnet-memory-manager** 記錄決策

**預期工時**：1-2 週

### 若流程判斷為 B（中等）

1. 將此模板發送給 **@dotnet-architect**
2. Architect 產出設計計畫
3. 交由 **@dotnet-developer** 實裝
4. **@dotnet-qa-reviewer** 審查
5. **@dotnet-memory-manager** 記錄決策

**預期工時**：3-5 天

### 若流程判斷為 C（小型 / 緊急）

1. 將此模板發送給 **@dotnet-developer**
2. Developer 直接實裝與本地測試
3. **@dotnet-qa-reviewer** 快速審查
4. **@dotnet-memory-manager** 記錄決策

**預期工時**：1-2 天

## 💡 常見問題

**Q1: 如果我提交的需求不確定流程，怎麼辦？**
A: 按最保守的估計回答（傾向複雜化），系統會推薦對應的流程。如果高估了，Architect 可以降級。

**Q2: 流程中途能改變計畫嗎？**
A: 可以，但必須重新評估。若在 Developer 階段發現設計有誤，Architect 需要調整計畫。

**Q3: 緊急修復真的不需要 Architect 嗎？**
A: 流程 C 針對 Bug 修復與小改動。若涉及架構變更，仍需升級到流程 A。
